## 4. 必须补进原方案的实施约束

1. **内容扩展是契约升级。** 当前 target、PREFIX、单一 advisory lock、cache tag、来源校验、preview、读回 URL/hash 和 effects 关联都绑定试点。增加目标身份时必须一起迁移；旧 C 版本和失败回执完整保留。[S03–S05]
2. **动态 token 尚未实现。** 当前校验拒绝 `{{` 及部分价格/地区数字，不提供受控 token。现有正则也不等于全语言事实校验。先支持稳定身份 token；动态价格 token 在事实视图和数据版本一致性完成后另开门禁。[S03]
3. **读优先级须按字段列出。** 不能简单写“后台覆盖源码”：活动实验、managed revision、SeoMeta、editorial、生成文案的当前消费者不同。只对已迁移字段启用明确顺序，保留本语言安全 fallback，禁止跨语言串用。[S11][S12]
4. **持久 attempt 不等于自动恢复执行器。** 当前 Action 在提交后立即执行分发，支持人工 retry；本轮未发现统一生产后台扫描器能够接管所有遗留 pending。补后台领取/lease/超时/退避/幂等执行，并用进程中断验收证明恢复。沿用事务性 Outbox 的原则即可，不必引入消息平台。[S04][S05][E01]
5. **统一展示保留原生状态。** 当前试点用 `verified`、`origin_invalidated`，历史 RFC 有另一套分发状态定义。先提供公共展示适配及 `native_status`，不能批量重写历史成 succeeded；“保存成功”与“公网核验成功”始终分开。
6. **公开数据版本不是 content epoch。** epoch 目前只保护受管内容；统计/价格快照、汇率日期另有含义。定义请求级事实视图及依赖身份，元数据与正文复用；分发回执保存实际渲染事实指纹。不要未经性能/兼容设计就对所有价格和内容加全局串行锁。
7. **来源按现有解析能力开放。** 后台只能配置已经登记的解析器、官方域名和地区/参数；不能把任意 URL、正则、SQL、脚本或浏览器代码作为普通设置执行。URL 校验还需覆盖重定向目标和内网地址风险。
8. **上新范围明确到模板和采集器。** 已有 App Store 或已登记官方 Web 能力的对象可纳入；新来源类型/新解析器仍需要程序发布。软件分类的公开模板、内容与 SEO 门禁不能因创建了产品而自动解除。
9. **内容解释中的事实先分类。** “适合谁”可以编辑；人数、周期、权益限制、购买条件必须有证据和复核身份。迁移 free text 前先区分，不能把全部原文直接当可信事实导入。
10. **权限沿用当前基础逐步扩展。** 现有 OWNER/EDITOR/VIEWER 中，EDITOR 可保存特定草稿、manage 仅 OWNER。内容第一批不扩大目录/价格权限；需要委派产品资料编辑时另补能力矩阵、服务端鉴权和越权测试。[S14]

| 变更 | 正式生效点与回执 | 恢复方式 |
| --- | --- | --- |

| 来源/映射/质量配置 | 激活已审阅修订，供新任务读取；记录配置影响范围 | 新任务切回兼容修订；运行中任务保持固定版本；旧产物另走审核 |

正式远程发布使用 `scripts/geosub_ops.py` 的 start/status/observe 流程；RELEASE 中 shell 控制器是服务器内部执行器，不重新绑到本地 SSH 生命周期。未知提交结果查同一回执，不自动重派。[S01]

## 10. 第一批实施：字段契约与生命周期边界

用户已批准按本清单开始第一批本地实施，保留数据与历史，真实推广继续关闭。本批 Architecture / L2：交付可校验的归属清单、只读边界判定、基线账本和下一批目标注册。生产 schema、数据、公开读路径、审核阈值、任务和 SEO 决策均保持原实现。

### A1：逐字段归属与已知冲突

[business-field-ownership.json](../geosub-backend/data/business-field-ownership.json) 登记 10 个核心 Prisma 模型的全部标量列及 SQL 补充列，共 165 个字段，另有 4 类 JSON/配置表面。每个数据库列只有一个目标业务 owner，关联 Prisma 名、当前写入者、读取消费者及受控动作。每个源文件引用带可检查符号。另外登记 86 处字面 SQL/Prisma 写入文件，区分历史回填、schema/函数定义、后台动作、运行服务和受控脚本；新增或移除字面写入位置会触发清单复核。

另登记一项实际隔离迁移发现的 schema 差异：`audit_logs.actor` 与 Prisma 的 `actor_id`，见下方验证记录。

当前范围为 products、plans、region_prices、price_observations、price_sources、seo_meta、faqs、collector_jobs、collector_job_runs、audit_logs；补充 SQL-only job_config、priority 和历史 product_source_profiles。SiteSetting 的内容命名空间、来源 spec、官网配置和组件账本单独登记。该范围不是全数据库认证：账号、流量、文章明细、汇率/税务/收入的独立维护服务继续遵守原规范；改变这些服务时需扩充相应逐列清单，不能因为本检查通过就声明它们已经迁移。

显式保留四项未完成的写入收口：套餐资料双写、产品 description 双写、产品自动公开耦合、旧 SEO 写入入口。`check:ownership` 验证声明范围的覆盖、单一 owner、字段映射和证据引用；新增字段漏登记或重复 owner 会失败。`--strict-cutover` 在这些冲突仍存在时拒绝通过。字面扫描不覆盖任意动态 SQL/动态模型代理，也不判断历史迁移中哪个函数最后生效；这部分仍需代码审阅。检查不授权任何运行时写入。

### A2：常规操作基线

[business-operation-baseline.json](../geosub-backend/data/business-operation-baseline.json) 为改编辑内容、改套餐显示名、改映射和新增产品四类操作登记当前入口与历史例证。两项源码变更例证链接真实 Git 提交；未测的部署次数、业务操作总数和公网确认耗时保留 null。

目前无法从 Git 提交数可靠还原全部日常操作、人工编辑耗时及每次公网回执，因此本批不计算虚假的改源码比例、零部署或发布耗时，也不把源码检查当作四个后台流程已经跑通。基线采集协议已固定；后续 canary 记录实际操作 ID、首次保存、失败/重试、实际网站/采集发布和公网回执，用相同窗口比较。这里的 null 是待测，不是零；收益验收在 E5 进行。

### A3：生命周期决策及生效范围

生命周期采用以下明确边界：

1. 正式价格由证据和审核规则决定；内容就绪或采集 succeeded 不能代替价格批准。
2. 目录负责产品/套餐身份及公开状态。已批准的 App Store、Spotify、Apple Music 自动流程保留原授权、样本、隔离与恢复规则；当前不改触发器或取消自动化。后续 C1 将符合条件的自动操作转为目录命令，和人工操作共用就绪检查与审计，而不是改成全部人工逐条批准。
3. 产品可公开、可索引、可进导航、可进 sitemap 分别判定。普通内容发布不改变任何一项；“质量合格”也不等于解除显式索引待审核或预算限制。
4. 后续迁移对象的公开就绪需分别有合格价格、内容和公开模板证据。公开模板证据包含适用分类/渠道、品牌资产门禁和身份兼容；缺任一项保持未知或阻断。已有对象在本批不重新审核、不回写历史状态。
5. 已有历史的套餐不通过普通资料修改改变 ID、slug 或周期；显示名属于目录资料。产品公开 slug/category 路径的调整需独立身份迁移和重定向，不能混入文案保存。执行层保护在 C1/C2 收口，不宣称本批已经阻断所有旧写入者。
6. 内容、配置、程序恢复各自进行；归档保留证据，原失败回执不改写，程序回退不撤销正式价格。真实推广与 SEO 收录是不同决策，真实推广保持关闭。

[publication-boundaries.ts](../ai-price-site/lib/publication-boundaries.ts) 将这些“分别判定、缺证据不通过”的规则实现为只读评估：保留数据库记录状态，另算各类资格与阻塞原因。它不写数据库、不改变现行政策、不执行自动发布。`qualifiedPrice` 必须来自既有审核服务，不可由前端复选框认定；尚未接数据源时保持 unknown。

可运行只读示例：

```bash
cd ai-price-site
npm run check:ownership
npm run report:publication-boundaries -- scripts/fixtures/publication-boundary-summary.json
```

示例为明确标记的本地状态夹具，不是生产数据。只有草稿、即便已有合格价格也不会被评估成已公开；缺失的内容/索引决策不会被填成已通过。若推广状态不是明确 false，独立保护项保持 unknown/blocked，不谎报已经关闭。

### A4 与 B1 前置：限定内容 canary
