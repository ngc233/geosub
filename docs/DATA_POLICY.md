# GeoSub 数据政策

状态：v2.10 规范基线  
生效日期：2026-08-25

## 1. 目标

GeoSub 的公开数据必须可追溯到明确来源、计费平台、地区、套餐、价格类型、采集时间和汇率基准。数据完整性优先于页面填充率。

## 2. canonical 数据链路

公开页面、地图、价格表、报告和 SEO 元数据必须从同一 canonical dataset 派生：

```text
官方或受控采集来源
  -> price_observations
  -> 自动/人工复核与质量状态
  -> published region_prices
  -> 公开读模型
  -> 页面、报告、SEO 与结构化数据
```

不得从当前 DOM、截图、营销文案或搜索摘要反向生成正式数据。

## 3. 核心实体与必备字段

### 3.1 产品与套餐

必须明确：产品、品牌、分类、套餐、计费周期、套餐状态、官方入口和数据来源范围。

相似名称的套餐不能仅靠显示名称区分；slug 和 canonical plan spec 是稳定身份。

### 3.2 地区价格

公开价格至少包含：

- 国家或地区代码。
- 当地数值和货币。
- 折算美元价格。
- 计费平台和计费周期。
- 来源名称或来源入口。
- 价格采集时间与汇率日期。
- 发布状态与数据质量。

税费、风险、购买条件和复核时间在有数据时附加，但不能代替上述价格身份。

## 4. 计费平台口径

- App Store、Web、Google Play 和其他平台是不同数据范围，不能静默混合。
- 当前价格页默认平台优先顺序与界面保持一致：App Store、Web、Google Play、全部诊断数据。
- 标题、最低价、最高价、基准价、覆盖地区数、地图、榜单和报告必须声明或继承同一平台范围。
- “全部”只能用于诊断或用户显式选择；不能作为默认统计口径制造更大覆盖数字。
- 分类卡和 SEO 摘要必须使用与目标落地页默认展示一致的平台口径。

## 5. 价格状态与质量

公开层只把符合发布策略的记录当作正式价格。状态至少区分：

- `verified`：证据和重复样本满足自动或受控复核要求。
- `estimated`：可解释估算，但不能与正式标价混淆。
- `pending_review`：等待核验，不参与正式极值和推荐。
- `stale`：超过允许新鲜度，不作为当前结论。
- `unknown`：数据不足。

页面不得把“有观测”写成“已核验”，不得为了完整列表把 pending 或 stale 混入正式排行。

## 6. 来源与证据

来源和 GeoSub 引用必须区分：

- **Source**：原始价格、汇率、税务或收入数据来自哪里。
- **Citation**：外部用户如何引用 GeoSub 整理后的数据集或报告。

来源状态应尽量具体到官方页面、App Store、受控提供方或人工整理。`Official website` 之类模糊描述不足以支持复杂数据结论。

不在公开前端展示长期依赖人工逐条核实、且没有可维护流程的字段。确需人工覆盖时必须记录独立证据、操作者、理由和时间，并保持例外属性。

## 7. 汇率

- 数据库保存价格对应的当地货币和折算时使用的汇率基准。
- 公开转换只使用可用且未过期的汇率。
- 缺失或过期时显示不可用或新鲜度警告，不使用硬编码回退汇率。
- 当前生产同步和过期门槛由运行环境及检查脚本控制；修改门槛属于数据政策变更。
- 页面必须区分价格采集日期、汇率基准日期和当前页面更新时间。

## 8. 税费与购买条件

- 税费说明是背景证据，不默认对 App Store 标价重复加税。
- 必须区分税费可信度、来源类型、处理方式和复核状态。
- 账号地区、付款方式、礼品卡和购买入口只有在有证据时显示为已确认。
- 未知条件显示未知或不展示，不得推断“可购买”“需要当地卡”等结论。

## 9. 购买力与巨无霸参照

- 收入负担和地区标价是两个不同维度。
- 收入数据只有在覆盖率、美国基准、指标有效性和新鲜度门槛全部通过时才发布。
- 当前完整性门槛包括至少 80% 价格地区覆盖和有效美国基准；具体实现以 `lib/affordability.ts` 为准。
- 巨无霸价格是生活化消费参照，不替代收入负担，也不直接给出购买建议。
- 没有当地巨无霸数据时明确显示缺失，不进行无依据插值；已批准的区域参照必须标注。

## 10. 新鲜度与异常处理

- 价格、汇率、税务、收入和套餐复核分别保存时间，不合并成一个“更新时间”。
- 生产门禁拒绝过旧正式价格、极端异常价格和无效低价。
- 采集失败不得删除上一个有效正式价格；应保留最后成功值并显示其真实日期。
- 数据更新导致极值或覆盖数变化时，所有派生输出必须在同一版本中同步。

## 11. 报告与导出

报告至少包含产品、套餐、地区、当地价格、统一货币折算、相对基准、税费说明、来源、价格时间、汇率时间、生成时间和数据版本。

- PDF 服务引用和分享。
- CSV/JSON 服务机器处理。
- 各语言页面下载对应语言报告。
- 每个产品/套餐使用稳定 canonical report URL，避免为每次生成创建可索引重复 URL。

## 12. 数据变更门禁

以下操作必须单独审批并先有可验证备份：

- 生产 SQL、批量回填、数据删除或状态批量提升。
- 修改价格审核函数、异常阈值或汇率过期门槛。
- 改变默认计费平台或统计口径。
- 用新数据源替换现有正式来源。

本地空数据库、测试夹具或影子迁移结果不能作为生产数据异常的证据。
