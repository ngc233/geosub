# GeoSub 工程规则

状态：v2.10 规范基线  
生效日期：2026-08-25

## 1. 工作边界

每项开发必须有明确的问题陈述、工作类型、范围、不变项和验收标准。

- Bug 不顺带重构或重设计。
- Improvement 不改变数据、URL 或核心业务规则，除非范围明确包含。
- Feature 在编码前需要 PRD。
- Architecture 在编码前需要 RFC、迁移和回退方案。

发现相邻问题时记录为后续任务；除非它阻塞当前正确实现，不得自行扩展范围。

## 2. 事实来源顺序

冲突时按以下顺序判断：

1. 当前用户明确批准的需求和边界。
2. 本目录中的产品、数据、SEO、测试和发布规范。
3. 当前生产实现和数据库事实。
4. 已通过测试保护的行为。
5. 旧交接文档、历史计划和讨论记录。

旧文档与当前代码冲突时，不得机械恢复旧行为；先报告差异。

## 3. 组件与设计

- 优先复用现有组件、语义 token 和交互模式。
- 不为单页创建已有通用组件的近似副本。
- 新组件必须定义 API、状态、响应式行为和可访问性。
- 页面组件负责组合，数据和业务规则应放入可测试的共享模块。
- 图标使用现有标准图标库或经过权利审核的品牌资源，不使用文本字符冒充操作图标。
- 公开品牌图标只使用已提交的本地文件或确定性回退，不能运行时依赖未审核远程资源。

## 4. Next.js 与客户端边界

- 修改 Next.js 行为前读取当前安装版本 `node_modules/next/dist/docs/` 中的相关指南。
- 默认使用服务端组件；只有真实交互状态需要客户端边界。
- 不把完整产品、套餐和地区图传入只需要少量字段的客户端组件。
- 公开价格与可抓取内容必须存在于服务器 HTML，不依赖交互后才出现。
- dynamic、cache 和 revalidation 决策必须说明数据新鲜度与失效行为。

## 5. 数据访问

- 公开请求只读取数据库中已缓存、可发布的数据，不在访客请求内运行浏览器采集。
- 查询返回页面需要的最小 DTO，不为方便把完整图传给前端。
- 不根据猜测添加索引；先记录真实查询计划和延迟。
- 缺失、过期或失败的数据必须诚实降级，不用硬编码值保持界面完整。
- 生产数据库变更与普通代码改动分开审批。

## 6. 安全与内容

- 不直接插入未经清理的存储 HTML。
- JSON-LD 通过统一安全序列化函数输出。
- 外链使用安全属性；用户输入、搜索和筛选参数经过验证和限制。
- `.env`、数据库 dump、日志、私钥、会话和管理地址不得进入 Git 或输出到对话。
- 不恢复公开默认管理员密码或绕过登录限流。

## 7. 错误、空态与可观测性

- 错误信息区分用户可恢复问题、数据不可用和系统故障。
- 用户操作失败必须有界面反馈和下一步。
- 后台任务记录排队、运行、成功、失败和跳过，不用按钮动画代替真实状态。
- 日志不得包含凭据、完整 SQL 参数或个人信息。
- 性能优化需要基线、目标和复测；不以源码大小或主观感觉代替用户指标。

## 8. Git 与提交

- 修改前检查分支、提交和工作树。
- 保留用户已有改动，不清理或覆盖无关文件。
- 一个提交只解决一个可描述的问题。
- 不把 UI、SEO、数据迁移、依赖升级和发布脚本混进同一提交，除非它们不可分割且 RFC 已说明。
- 提交前运行 `git diff --check`，检查敏感信息和意外生成文件。
- 不使用破坏性 reset、checkout 或清理命令处理未知改动。

## 9. 依赖与运行时

- Node 运行时固定在仓库支持范围 `>=22 <23`。
- 新依赖必须说明用途、包体影响、维护状态、许可证和替代方案。
- 不为简单逻辑引入大型库。
- 锁文件变化必须与依赖声明一致，并通过 `npm ci` 验证。

## 10. PR 最低信息

每个 PR 或等价提交说明应包含：

- 问题与用户影响。
- 工作类型和明确范围。
- 不变项。
- 实现摘要。
- 测试与视觉验收证据。
- 数据、SEO、性能、迁移和回退风险。
- 未解决问题和后续观察计划。

## 11. Ready 与 Done

### Definition of Ready

进入开发前至少满足：

- 用户问题和目标明确。
- 工作类型、页面模板和受影响范围明确。
- 数据来源和统计口径明确。
- SEO 与索引影响已判断。
- 设计状态和响应式策略已定义。
- 验收标准、依赖和回退方向明确。

### Definition of Done

只有满足以下条件才可称为完成：

- 实现符合批准范围和相应规范。
- 自动化测试、类型、Lint 和适当构建通过。
- 用户可见变更完成桌面、移动、亮色和暗色验收。
- 数据、SEO、可访问性和错误状态已核对。
- 文档和实验记录更新。
- 工作树只包含预期文件。
- 若已发布，线上版本、健康检查和回退点已确认。

代码完成但尚未完成真实环境或视觉验收时，必须明确标为“实现完成，验收未完成”。
