# 采集器与网站独立发布（2026-10-20）

类型 Architecture，风险 L3。用户已明确批准实现、推送、验证后上线，要求前台持续可访问。

## 范围与边界

- 网站仍使用 rolling-state.json / current.env / live。新增 collector-state.json / collector-current.env / collector-live，只切换 collector-jobs 服务的程序来源，其他定时任务不迁移到新组件。
- 采集组件包含 geosub-backend 代码及依赖；数据库输入必须与当前网站已部署版本完全一致。数据库函数变更不冒充纯采集发布，必须先走已授权的兼容迁移发布。
- 采集发布只暂停 collector-jobs.timer，等待现有服务结束并取得与手动采集共享的文件锁；不停止运行中的任务。超时拒绝切换，恢复原定时器状态。
- 批次在取得锁后解析真实目录，固定本批次代码；新批次读取 collector-live。后台手动与定时采集使用相同入口、锁和环境。
- 网站构建保持独立目录；网站发布和回退保留已有采集器版本，不覆盖其服务配置。首轮需要一次滚动网站更新接入手动入口，此后采集发布不构建或重启网站、不修改代理、不操作内容围栏。
- 公共报告刷新读取原子发布的当前网站运行信息，避免采集批次跨网站切换时使用错配的端口与构建令牌。

## 数据库与版本

按实际 Git 输入比较 SQL、Prisma schema/migrations、迁移清单和迁移执行器，未知变化保守视为需要数据库路径。无变化时不执行 SQL/Prisma 迁移或 baseline 写入，明确记录 skipped。仍保留只读数据库健康和部署后迁移账本检查。

有变化时维持精确哈希许可、备份校验和原兼容迁移门禁。无数据库变化时不为迁移暂停全部定时任务，也不新建迁移备份；回退使用组件/网站保留构建，不恢复数据库。定期备份任务继续运行，迁移发布仍强制新备份。

仓库版本仍保持五处一致作为候选包版本。实际网站和采集器分别记录已部署版本/SHA，可以不同；后台网站版本仅代表网站。控制脚本安装须核对候选确切提交与当前组件版本，不得用较旧的控制脚本覆盖新控制目录。

## 验收与失败处理

- 覆盖无迁移输入、有新增迁移、历史迁移修改、仅 Prisma/清单变化，以及采集组件数据库不兼容拒绝。
- 覆盖采集发布准备失败、运行中等待/超时、定时器状态保持、切换失败恢复、显式回退、网站发布保留采集版本。
- 实际 Bash/Node 入口测试覆盖符号链接、参数透传、锁后目录解析和网站运行信息更新。
- CI 全部门禁通过后按标准脚本部署。上线期间持续采样公网首页、套餐页、健康端点与源站健康；记录状态、时延及网站进程身份，不能仅凭脚本退出码宣称无中断。
- 生产采集独立发布/回退演练中网站 PID、启动时间、代理配置须不变；核对真实采集与报告刷新。网站首轮接入走双实例切换。
- 仅实际数据库变更需要新的迁移备份。采集/网站回退都不恢复数据库；旧构建、组件目录和操作账本保留。

不变项：采集范围、频率、价格审核阈值、SEO 实验、推广和内容发布围栏设置。
