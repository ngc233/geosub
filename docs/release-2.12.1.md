# 2.12.1：定时任务启动可靠性修复

类型：Bug / L3。2026-10-17 用户批准修复定时任务与发布流程、防复发测试及恢复后完整调度周期观察，之后继续补齐监测和发布记录。真实推广保持关闭。

## 问题与范围

2.12.0 的 git archive 保留了仓库脚本非可执行模式，systemd 直接执行 run-system-task.sh，导致 analytics_aggregation、collector_runner、discovery_scan 返回 203/EXEC。旧目录有人工执行位，新构建缺少该状态；同入口的其他低频任务也有风险。发布时检查 timer active/enabled 不能证明下一次任务成功。

所有任务模板明确使用 /bin/bash 启动入口和 shell 子命令。滚动发布与回退统一规范化保留版本的旧模板，在切换前用实际服务用户检查解释器可执行及每个脚本可读/语法；发布后核验安装的任务入口并检查全部八个受控任务失败状态。生产应急修复使用 check-task-launch.mjs --repair：完整预检、备份单元、仅修改解释器、不改变调度/运行代码、不重启网站、不清除失败记录。随后分别真实执行失败任务确认恢复。

## 验收与回退

防复发测试以真实 0644 shell 文件执行双层入口，验证参数及非零退出码透传；遍历所有十个任务模板检查解释器及源脚本；共八项发布测试。未知 ExecStart、多入口或覆盖配置拒绝。恢复不能用 reset-failed 冒充成功。

新补丁沿用正式 CI → 控制脚本安装 → 滚动升级/备份/健康回读流程。内容读取契约未变，登记精确 2.12.1 → 2.12.0 兼容回退；新增表不删、内容不重发、真实推广关闭。任务单元修复保留旧单元备份；应用回退仍规范化旧模板，避免重新引入权限故障。

## 状态

本地专项测试通过，正在运行完整发布门禁。尚未发布 2.12.1；完整周期至少覆盖修复后每个启用定时器的一次自然触发和成功结果，日任务未触发前不得宣布通过。监测与发布记录后续收尾以实际证据为准。

首次生产尝试被数据门禁拦截并自动回退至 2.12.0：Type=oneshot 执行中为 activating，原 is-active 判断漏掉它，采集中的新观测触发精确本地价格门禁（59 条）。这不是成功部署，也未跳过质量门禁。修正后仅 inactive/failed 视为已结束；activating/active/deactivating/reloading 和未知状态均阻止迁移。补充专项测试；等待真实采集结束后再按新提交 CI 和正式流程重试。已完成的任务启动修复随旧模板规范化保留。
