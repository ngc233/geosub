# GeoSub 测试与验收矩阵

状态：v2.11 小团队规范基线

生效日期：2026-08-27

## 1. 原则

测试范围由变更风险决定，但任何用户可见改动都不能只依赖“页面能打开”。自动化测试、浏览器验收、数据核对和生产验证解决不同问题，不能互相替代。

## 2. 风险分级门禁

| 等级 | 必须验证 |
| --- | --- |
| L0 | 文档链接、格式、范围、`git diff --check`；不要求构建或全量测试 |
| L1 | 聚焦回归测试、受影响代码的类型/Lint；影响渲染时构建；UI 验收目标页面四态 |
| L2 | 完整相关测试、类型、Lint 和生产构建；推送后通过 CI；按范围增加数据、SEO或浏览器矩阵 |
| L3 | L2 全部门禁，加备份、迁移、回退演练和真实环境验证 |

四态验收只覆盖受影响页面、共享组件的代表页面和必要回归页，不要求每个小改动重复巡视全站。

## 3. 固定测试层级

### 3.1 静态与单元测试

适用于纯函数、文案、路由、政策、状态判断和组件静态约束。

最低要求：

- 新业务规则有正常、边界和失败用例。
- Bug 修复先增加能复现问题的回归用例。
- SEO、数据口径和发布门禁使用精确断言，不只做文件存在检查。

### 3.2 类型与 Lint

所有代码改动运行：

```bash
npm run typecheck
npm run lint
```

不得通过扩大 `any`、关闭规则或忽略错误来让门禁变绿，除非有明确 RFC。

### 3.3 生产构建

涉及路由、服务端组件、元数据、数据库读模型、环境变量、动态缓存或依赖时必须运行生产构建。

构建成功只证明编译和预渲染可完成，不证明交互、数据或视觉正确。

### 3.4 浏览器验收

用户可见 UI 必测：

- 桌面 1280×720，亮色和暗色。
- 移动 390×844，亮色和暗色。
- Chrome；发布级核心流程补充 Safari 或等价 WebKit 检查。
- 键盘 Tab、Enter、Space、Escape 和可见焦点。
- 页面级横向溢出、遮挡、布局跳动、图片失败和控制台错误。

触控设备不使用 hover 作为唯一入口。地图点、弹窗、Tabs、横向滚动和折叠区域必须在移动端实际操作。

### 3.5 数据验收

价格相关变更至少核对：

- 产品、套餐、计费周期和默认平台。
- 正式地区数量与价格表一致。
- 最低、最高、美国基准和价差计算。
- 当地货币、折算币种、汇率日期和价格日期。
- 税费、来源、质量和复核状态。
- 缺失、过期、pending、estimated 和 stale 不进入正式结论。

页面、地图、SEO 元数据、JSON-LD 和报告抽查同一数据样本。

### 3.6 SEO 验收

固定检查：

- title、description、H1。
- canonical、hreflang、robots。
- JSON-LD 与可见内容。
- sitemap URL 预算、重复、正式路径和 HTTP 状态。
- 旧 URL 到正式 URL 的单跳永久重定向。
- staged locale 不被意外推广。

### 3.7 可访问性

- 所有操作支持键盘。
- Modal/Drawer 管理焦点并可用 Escape 关闭。
- 图标按钮有可访问名称。
- 输入有标签、错误信息和状态关联。
- 颜色不是唯一状态表达。
- 正文与控件以 WCAG AA 为目标。
- reduced-motion 下禁用非必要动效。

### 3.8 性能

只有用户路径或服务指标受影响时进行专项优化，并记录改前和改后：

- LCP、CLS 和关键交互响应。
- 压缩传输大小，而非只看解压 HTML。
- API 和数据库查询 p50/p95。
- bundle 或客户端边界变化。
- 缓存命中、失效和数据新鲜度。

没有测量证据时不增加索引、不拆分组件、不更改缓存策略。

## 4. 变更类型矩阵

| 变更 | 单元/静态 | 类型/Lint | 构建 | 浏览器四态 | 数据 | SEO | 生产健康 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 文档 | 按需 | 否 | 否 | 否 | 否 | 否 | 否 |
| 纯文案 | 是 | 是 | 是 | 目标页 | 按需 | 是 | 发布时 |
| 组件样式 | 是 | 是 | 是 | 是 | 按需 | 可见内容变化时 | 发布时 |
| 交互逻辑 | 是 | 是 | 是 | 是 | 按需 | 可抓取内容变化时 | 发布时 |
| SEO 政策 | 是 | 是 | 是 | 目标页 | 是 | 全量 | 是 |
| 数据读模型 | 是 | 是 | 是 | 目标页 | 全量 | 是 | 是 |
| 数据迁移 | 是 | 是 | 是 | 受影响页 | 全量+影子验证 | 是 | 备份+全量 |
| 发布脚本 | 是 | 按语言 | 按需 | 否 | 迁移路径 | sitemap/health | 全量 |

## 5. 核心回归页面

L2/L3 运行时发布前至少覆盖；L1 只覆盖目标页和受影响共享组件的代表页面：

- `/zh`
- `/zh/ai-pricing`
- `/zh/ai-pricing/chatgpt`
- `/zh/ai-pricing/chatgpt/plus`
- 一个多套餐的非 ChatGPT 产品页。
- `/zh/streaming-pricing` 及一个套餐页。
- `/en` 及对应英文套餐页。
- 搜索、语言切换和货币转换。
- `/api/health`、`/robots.txt`、`/sitemap.xml`。

变更涉及报告、文章、地区页或后台时补充对应代表页面。

## 6. 标准命令

L1 从聚焦测试开始，并按受影响范围补充类型、Lint 或构建。L2/L3 的代码门禁：

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

数据库健康时的完整门禁：

```bash
npm run preflight:full
```

SEO 变更额外运行：

```bash
npm run check:seo
npm run check:sitemap
```

仓库级发布使用 `scripts/release-check.ps1`，不得用零散命令冒充完整发布门禁。

## 7. 证据记录

完成报告必须区分：

- **已验证**：实际运行并通过。
- **结构性检查**：只确认代码或文件结构。
- **未验证**：需要浏览器、数据库、账号或生产环境。

不得把 TypeScript 通过写成“功能已验证”，也不得把桌面截图写成“响应式已验收”。
