## 门禁与不变项

- 无依赖 Node 检查器可以读取工作树或指定 Git 提交的文件，校验所有版本字段及 SemVer 递增。
- 本地 release-check 默认只验证同步；指定 BaselineRef 可比较分支。publish-release 无条件获取远端分支并检查递增，不能用 SkipChecks 或 NoTag 绕过。
- upgrade 停服前核验干净仓库、current.env 和固定候选提交；安装阶段不能重新获取另一个未经检查的目标。安装前再次确认 SHA 与文件版本。
- 标准生产部署目前使用统一仓库。旧分离布局、无 Git 的复制目录或缺失成功记录都明确拒绝；先核对并迁移到统一仓库，不隐式放行。
- 不修改数据库、数据回填、SEO 实验、周报默认口径、服务调度或旧的访问计数。prepare-release 保留锁文件原缩进，避免只改版本却重写全部依赖差异。

## 首次上线迁移与回退

线上 9f4ed33 的升级脚本尚无新门禁。首次部署 2.10.0 前，先获取已推送并通过 CI 的明确提交，用本候选检查器读取该提交的 Git 文件并与服务器 `/opt/geosub/releases/current.env` 比较。确认是 2.9.0 → 2.10.0 后，仍执行标准 upgrade.sh 的备份、构建、迁移和健康流程，完成后确认实际提交及后台版本。新脚本随代码安装，之后的标准升级自动执行停服前检查。不得把本地通过描述成生产已受保护。

回退应用仍使用标准 rollback.sh，提供部署 ID 与确认令牌，校验备份后重建旧提交；不恢复数据库，不伪造成功版本记录。回退至旧版本也会恢复旧升级脚本，下次升级必须重新执行首次上线检查。此修复本身无 schema 迁移。
