## 回退顺序

新增 schema 后，旧采集器与新网站的 Git 数据库输入不同，
collector-release 的显式旧组件回退会按原门禁拒绝；不能承诺此时可单独回退旧组件。
保留这种拒绝，不绕过输入检查。

- 网站升级失败：标准控制器恢复原入口与任务状态，新增账本不删除；核对原生失败回执。
- 采集切换失败：既有恢复回调还原旧组件及私有/公开回执，保留已验证的新网站和数据库。
- 整批显式回退：先按本次成功网站 attempt 回到已保留的旧网站，再按成功采集 attempt
  回退旧采集组件，逐项核对原生回执与健康。原旧网站/采集输入必须现场重新比对一致。
  网站回退保留独立采集组件，两个步骤不并发；中间状态使用已经验证的追加 schema。
- 不恢复旧库、不删版本历史、不重建保留构建。数据库恢复是另一项单独审批操作。
- 连接断开或结果未知，只查询同一请求 status，不重发 start。
