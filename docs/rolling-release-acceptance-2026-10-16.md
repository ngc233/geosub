# 2.12 滚动发布正式脚本验收（2026-10-16）

结论：本地代码门禁及正式脚本的隔离预生产验收通过，上一轮的“正式发布流程未接通”阻断已补齐。可以进入用户授权后的推送、远端 CI 与生产首次接入流程。本轮未推送、未部署、未修改生产代理/服务/数据库；真实推广保持关闭。

## 实现

- 正式 upgrade.sh / rollback.sh 默认进入 rolling-v1；安装器从固定、已 fetch 且通过版本检查的提交安装 root 管理的控制目录。不会覆盖运行中的 checkout。
- 新版独立目录安装、构建，旧版保持服务；静态资源只增不删，路径冲突拒绝覆盖。服务、配置、版本和尝试记录关联保留。
- 迁移仅允许已审核的新增文件哈希，现有 SQL 改删和未知迁移拒绝；保留真实备份、内容发布围栏、任务暂停及等待、完整健康门禁。
- 代理先检查实际配置，再重载与源站回读；失败恢复旧入口、任务路径、发布记录及原定时器状态。回退使用保留构建，不重新安装或构建，不恢复数据库。
- 过期回退、重复版本和接入滚动后误用旧维护模式均拒绝。
- 原有真实 IP/转发头保留。后台及健康接口 no-store；只对静态资源设置 immutable；本轮未增加公开页面缓存策略。

## 故障与修复记录

1. 首轮 sitemap 检查错误地把本地访问地址当成 canonical，正式健康门禁拒绝并自动恢复旧版本。已分离检测地址与 canonical；所有 URL 状态检查都落在预生产，不使用线上响应冒充验证。
2. 用测试专用代理包装器在候选配置中注入非法指令；真实 OpenResty -t 拒绝，新版未投入服务，正式脚本恢复旧配置、任务路径和原定时器状态。故障包装器未进入仓库或生产。
3. 旧版本测试原先默认走停站路径，新增默认模式后触发 Linux root 门槛。测试改为显式 maintenance-v1，保留原版本拦截断言；新路径另由真实 Linux 环境验证。

## 证据边界与发布前提

- 隔离 Git 远端和提交仅用于测试当前未提交工作树，不能当作生产 SHA。正式发布必须先推送明确提交、通过远端 CI。
- OpenResty 的真实重载和 systemd 任务管理已执行；预生产 PostgreSQL 使用 native 客户端连接专用本机库，生产仍默认 Docker 传输。
- 已只读核实生产使用 host 网络且已有站点目录挂载；接入方案复用单站点挂载，不要求重建共享代理。实际生产首次接入仍需授权，按运行手册备份并替换单站点代理片段，配置只绑定回环的探测入口、运行 adopt；这属于发布步骤，本轮没有执行。
- 标准健康检查保留两项警告：一条历史 App Store 价格超过 14 天；隔离环境无真实 Cloudflare 缓存命中头。没有修改数据时间或伪造 CDN 证据。公网缓存回读必须在获准部署后执行。
- 不承诺所有环境绝对零停机。5990 次零失败是本次隔离环境实测结果。旧后台表单可能需要刷新，不自动重放写操作。
- 资源不自动清理，备份仍按已有保留策略；数据库恢复和旧资源清理须独立评估。
