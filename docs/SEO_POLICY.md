# GeoSub SEO 政策

状态：v2.10 规范基线  
生效日期：2026-08-25

## 1. 原则

GeoSub 的 SEO 目标是让完整、可信、具有独立搜索价值的页面被发现，而不是最大化 URL 数量。

任何 SEO 改动都必须同时保护：

- 用户看到的内容与搜索摘要一致。
- canonical、hreflang、robots 和 sitemap 口径一致。
- 页面价格、地区数量和来源与实际默认展示范围一致。
- 搜索增长不以牺牲数据可信度或制造重复页面为代价。

## 2. 当前索引边界

- 站点已准备并可访问多种语言。
- 当前主动允许索引和进入 sitemap 的语言仅为中文 `zh` 与英文 `en`。
- 其他语言保持可访问、可跟随，但在内容、本地货币、税费、搜索意图和套餐覆盖门槛达标前不得主动推广。
- 扩大索引语言必须修改统一策略并通过 SEO 检查，不能只在单页解除 `noindex`。

代码事实来源：`ai-price-site/lib/seo-indexing-policy.ts`。

## 3. URL 与 canonical

- 正式套餐页使用稳定路径 `/{locale}/{category}/{product}/{plan}`。
- 旧 `?plan=` 查询参数必须单跳永久重定向到正式套餐路径。
- 每个可索引页面必须自 canonical；不得让多个不同页面 canonical 到同一内容来掩盖架构重复。
- canonical 不包含追踪参数、临时实验参数或界面状态。
- URL 结构变更属于 Architecture，需要迁移表、重定向测试、sitemap 更新和回退方案。

## 4. hreflang

- hreflang 只指向真实存在、内容可访问的语言版本。
- 语言可访问不等于允许索引；robots 政策仍由语言和页面质量共同决定。
- 新语言上线必须同时验证 HTML `lang`、方向、默认币种、canonical 和所有互指语言。

## 5. robots 与 sitemap

- 内部、测试、草稿、历史续订套餐和质量不达标页面必须 `noindex`。
- `noindex` 页面原则上不进入 sitemap。
- 生产 sitemap 动态生成失败时必须失败关闭，不允许静默退回不完整静态列表。
- sitemap 受明确预算控制；不得因为新增产品或语言自动指数级扩张。
- 产品概览通过质量门槛后可进入 sitemap；套餐页按明确的推广名单分批进入。
- 地区页只有具备独立内容、数据完整度和搜索需求时才允许进入 sitemap。

当前预算事实来源：`ai-price-site/lib/seo-indexing-policy.ts` 与 `ai-price-site/scripts/check-sitemap-budget.mts`。

## 6. 元数据

### 6.1 Title

- 直接表达页面任务、产品与套餐。
- 可包含年份、价格范围或覆盖地区数，但数值必须来自页面同一 canonical dataset 和默认平台范围。
- 给 `- GeoSub` 后缀保留长度；英文标题原则上控制在完整结果可读范围内。
- 不堆叠国家、货币和营销形容词。

### 6.2 Description

- 说明页面能回答什么，并使用可验证的实时事实。
- 价格极值、地区名称、基准价和覆盖数必须与页面一致。
- 不承诺跨区购买成功，不把未知税费或支付条件写成事实。
- 数据不可用时回退到不含具体价格的通用描述。

### 6.3 H1 与首屏承诺

- H1 描述产品与套餐，不为追求点击频繁改变。
- 搜索摘要中的关键价格承诺应在首屏可见。
- 元数据实验不得制造搜索结果与落地页不一致。

## 7. 结构化数据

- 结构化数据必须与可见内容一致并通过统一安全序列化。
- 价格比较数据优先使用适合数据集、文章、FAQ、面包屑或网站实体的类型。
- GeoSub 不能证明直接销售时，不使用 `Product`、`Offer` 或 `AggregateOffer` 暗示交易能力。
- 不虚构数据重用许可、评分、库存、税费或购买可用性。
- 折叠但保留在服务器 HTML 的内容可以进入对应结构化数据；仅客户端临时状态不得伪装成可抓取事实。

## 8. 内容与内链

- 分类页链接到产品概览，产品概览链接到当前套餐，套餐页链接到相关地区和指南。
- 内链必须帮助完成相邻任务，不为关键词密度重复堆叠。
- 地区页和指南必须反向链接到其数据来源套餐页。
- 空入口、未发布指南和没有数据的分类不进入导航。

## 9. SEO 实验

每个实验必须记录：

- 唯一实验 ID、目标搜索引擎、页面、基线和假设。
- 唯一主要变量以及明确不变项。
- 数据来源、开始日期、最早判断日期和样本门槛。
- 主要指标、排名与展现 guardrail、保留或回退规则。

执行规则：

- 一个页面同一时间只运行一个主要 SEO 实验。
- 部署日为第 0 天，不作为完整观察日。
- 默认至少观察七个完整 settled-data 日，并确认搜索引擎已重新抓取。
- 观察期间不改目标页 URL、canonical、robots、H1、核心正文或内部链接结构。
- 不把一个页面的结果直接扩展到全站；先在第二个相近页面复制验证。
- Google 与 Bing 分开看，不用一个搜索引擎的结果替代另一个。

## 10. 发布门禁

SEO 相关变更至少通过：

- `npm run check:seo`
- `npm run check:sitemap`
- SEO 静态和策略测试。
- 生产构建。
- 线上 title、description、canonical、robots、hreflang 和 H1 核验。
- sitemap URL 预算、重复 URL、正式路径和 HTTP 200 检查。

提交 IndexNow 或操作站长平台属于外部状态变更，必须在部署成功和线上内容准确后执行并记录结果。
