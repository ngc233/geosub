# GeoSub 产品章程

状态：v2.11 小团队规范基线

生效日期：2026-08-27

适用范围：公开站、管理后台、数据管道、SEO、报告导出与发布流程

## 1. 产品定位

GeoSub 是全球数字订阅价格情报产品。它整理并解释经过核验的地区订阅价格，帮助用户理解本地标价、折算价格、税费、汇率、数据新鲜度、购买力和订阅条件。

GeoSub 的优先级固定为：

1. 数据权威：公开结论必须可解释、可追溯、可验证。
2. 搜索增长：优先提升完整页面的价值，不批量制造薄页面。
3. 决策效率：让用户快速找到最低价、基准价、地区差异和证据。
4. 合理转化：引导用户继续比较、阅读相关说明或访问官方来源。

## 2. 目标用户

- 想确认某项数字订阅在不同国家或地区价格的普通用户。
- 需要引用全球价格数据的研究者、媒体、博主和分析人员。
- 需要核查价格来源、汇率日期和数据口径的专业用户。
- 负责采集、复核、内容和发布的 GeoSub 内部运营人员。

## 3. 用户核心任务

用户应能在一个产品或套餐页面完成以下任务：

- 确认当前比较的是哪个产品、套餐、计费周期和计费平台。
- 找到最低价、最高价、美国基准和覆盖地区数。
- 查看当地货币价格、统一货币折算和相对基准差异。
- 核对价格、汇率、税费和套餐的更新时间与可信状态。
- 区分公开标价、购买力结论和尚未核实的购买条件。
- 进入官方来源、相关地区分析、相关套餐或可引用报告。

## 4. GeoSub 不是什么

GeoSub 不是：

- 订阅代购、支付、账号迁移、礼品卡销售或 VPN 服务。
- 对跨区购买一定成功的承诺工具。
- 仅凭汇率差异给出购买推荐的网站。
- 用无法自动核实的人工标签制造确定性结论的平台。
- 为增加收录量而生成大量重复地区页或语言页的内容农场。

## 5. 产品原则

### 5.1 事实优先

无法从正式价格、可信数据源或明确证据得出的信息，必须显示为未知、待核验或不展示。不得用推测填补空白。

### 5.2 口径一致

标题、摘要、统计卡、地图、价格表、报告和结构化数据必须使用同一计费平台和同一过滤范围。页面默认展示 App Store 时，不得把 Web 或其他平台记录混入覆盖数和价格极值。

### 5.3 渐进披露

首屏回答产品、套餐、价格范围和新鲜度；详细税费、证据、风险和购买力按需展开。不能为了“信息完整”让首屏成为后台报表。

### 5.4 模板化扩展

新增产品、套餐、地区或内容应进入已有页面模板和数据模型。除非现有模板无法满足经过批准的新用户任务，否则不得为单个产品复制一套页面结构。

### 5.5 无证据不扩张

历史趋势、购买难度、支付方式、礼品卡支持和国家级推荐等能力，只有在数据覆盖和验证标准确定后才能发布。

## 6. 需求分类

所有工作在进入开发前必须归入以下一种类型，并按 `WORKFLOW.md` 标记 L0-L3 风险：

- **Bug**：现有行为与已批准规范或已验证数据不一致。只修复缺陷，不顺带重设计。
- **Improvement**：不改变核心能力的小范围体验改进。必须说明用户问题和验收标准。
- **Feature**：新增用户能力、入口或数据输出。L1 使用简短任务说明，L2/L3 使用与风险相称的 PRD。
- **Architecture**：改变跨模块约束、设计系统、数据模型、缓存或发布链路。L2/L3 使用与风险相称的 RFC。

## 7. 版本策略

规范基线版本与应用 `VERSION` 相互独立。更新产品开发规范不自动改变网站版本，也不构成生产发布。

每个应用版本仍只承载一个主要结果，不得把 UI 重构、SEO 扩张、价格算法和依赖升级混为同一发布主题。具体版本目标以当前路线图或产品负责人最新决定为准，旧路线建议不自动成为执行要求。

## 8. 成功标准

产品改动至少应改善一个明确指标，同时守住数据和技术门禁：

- 用户在十秒内找到最低价、基准价、更新时间和数据来源。
- 目标搜索页面的点击率改善，且排名与展现没有持续性恶化。
- 公开价格、平台范围和覆盖地区数不存在跨模块冲突。
- 移动端无页面级横向溢出，主要操作可触达。
- 发布后健康检查无失败，且可通过已验证版本回退。

具体指标、样本量和观察窗口必须写入对应任务说明、PRD 或实验记录，不能用“看起来更好”作为唯一完成标准。
