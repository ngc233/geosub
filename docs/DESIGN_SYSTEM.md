# GeoSub 前台设计系统

状态：v2.10 目标规范，渐进迁移  
生效日期：2026-08-25

## 1. 设计目标

GeoSub 的视觉语言是现代、轻量、清晰的数据情报工具。页面应让价格差异和证据成为视觉主角，而不是用大量装饰色、动画或营销组件抢夺注意力。

核心原则：

- 白色或近白表面配合轻灰页面底色，暗色模式使用对应语义表面。
- 荧光绿只用于品牌识别、最低价、正向状态和少量主要行动。
- 高价使用克制的暖红；基准和普通信息使用中性色阶。
- 卡片靠层级、边框和阴影区分，不用随机强调线。
- 动效用于解释状态变化，不能造成抖动、循环呼吸或布局位移。

## 2. 语义 token

v2.10 应逐步将前台颜色和尺寸迁移为语义 token。新组件和被重构的组件不得再新增无说明的颜色值。

最低要求：

```text
--color-bg-page
--color-bg-surface
--color-bg-surface-raised
--color-bg-subtle
--color-border-default
--color-border-strong
--color-text-primary
--color-text-secondary
--color-text-muted
--color-accent
--color-accent-soft
--color-price-low
--color-price-low-soft
--color-price-high
--color-price-high-soft
--color-focus
--radius-control
--radius-card
--shadow-control
--shadow-card
--shadow-card-hover
--spacing-section
```

亮色与暗色主题分别给 token 赋值。组件只使用语义，不自行决定“白色卡片”或“黑色文字”。

现有 Tailwind 色值属于遗留实现，不要求一次性替换；文件被实质修改时，应优先迁移该组件涉及的语义，不顺带重写无关页面。

## 3. 色彩规则

### 3.1 主色

荧光绿是 GeoSub 的识别色，不是所有交互的默认底色。可用于：

- Logo 辅助识别。
- 全球最低价、低价端点和已确认的正向状态。
- 一个区域内的主要行动或选中指示。
- 键盘焦点与少量状态图标。

同一可视区域原则上只保留一个高显著绿色行动。

### 3.2 数据色阶

价格色阶必须具有顺序意义：

- 最低价：荧光绿或清晰的绿色端点。
- 较低：低饱和浅绿。
- 接近基准：中性灰或灰绿。
- 较高：低饱和暖灰或浅红。
- 最高价：明确但不过度刺眼的暖红。
- 无数据：浅灰，不使用价格色。

颜色不能成为唯一信息载体；必须同时使用“最低价、基准、最高价”、数值、符号或位置。

### 3.3 禁止项

- 同一模块同时使用蓝、紫、橙、绿等多个无数据语义的强调色。
- 用红色表示普通“更贵”之外的非错误内容。
- 用近黑绿色冒充最低价，导致用户无法一眼识别。
- 为单个页面创造新的品牌主色。

## 4. 字体层级

现有 `.gs-page-title`、`.gs-section-title`、`.gs-card-title`、`.gs-body`、`.gs-meta` 和 `.gs-badge` 是前台排版基线。

规则：

- 每页只能有一个 H1。
- 正文以 14–16px、舒适行高为主；移动端不得为了塞入更多内容压到不可读。
- 价格和百分比使用等宽数字。
- 元信息小于正文，但对比度必须足以阅读。
- 不用超大标题挤压首屏的数据任务。

## 5. 间距、圆角和阴影

- 控件、卡片和弹窗使用有限的圆角层级，不为每个模块指定新半径。
- 页面区块间距大于卡片内部间距；卡片内部信息组间距大于标签与数值间距。
- 默认卡片以细边框和轻阴影建立层级。
- hover 只允许轻微上移或阴影加深，不改变可点击区域，不改变相邻元素布局。
- 触控设备不得依赖 hover 动画传达选中状态。

## 6. 组件规范

### 6.1 Button

只保留四类：Primary、Secondary、Tertiary、Destructive。

- 标准图标来自现有图标库，不用字符箭头模拟操作图标。
- 数据涨跌中的 `↑`、`↓` 属于数值语义，可保留。
- 外链按钮只显示一个标准外链图标。
- 图标按钮必须有可访问名称和足够触控面积。
- 同一区域不得出现多个相同目标的按钮。

### 6.2 Card

- 使用统一 surface、border、radius 和 shadow。
- 价格卡的颜色只表达数据位置或状态。
- 整卡可点击时，内部不得再放产生冲突的重复主链接。
- hover 不得引起无限抖动或命中区域反复变化。

### 6.3 Input 与筛选

- 标签、输入值、占位符和错误状态完整。
- 搜索弹窗的遮罩覆盖整个视口，点击任意遮罩区域和按 Escape 均可关闭。
- 控件不能在窄屏被截断；横向滚动区域要有清晰边界。

### 6.4 Table

- 桌面端优先支持列对齐和快速扫描。
- 移动端转为信息卡或渐进展开，不压缩为不可读宽表。
- 本地价、折算价、相对基准、税费、来源和日期保持固定语义顺序。

### 6.5 Modal 与 Drawer

- 使用统一遮罩、表面、关闭按钮和焦点管理。
- 桌面使用居中 Modal；移动端根据任务可使用 Bottom Sheet。
- 打开后锁定背景滚动；关闭后焦点返回触发器。
- 不得出现上半屏模糊、下半屏未遮罩的割裂状态。

### 6.6 Tabs

- 套餐 Tabs 表达同一产品内的互斥选择。
- 当前项、hover、focus 和 disabled 状态明确。
- 选项过多时允许容器内横向滚动，不让整个页面横向滚动。
- “查看全部套餐”属于相邻导航，不伪装成另一个 Tab。

## 7. 交互状态

每个交互组件必须定义：default、hover、active、focus-visible、disabled、loading、error 和 empty；不适用状态需要在实现说明中指出。

异步操作必须在 100ms 内提供状态反馈。失败必须说明用户下一步，而不是静默或只写控制台。

## 8. 响应式与可访问性

- 必测视口：桌面 1280px 和移动 390px；必要时补充平板断点。
- 必测亮色和暗色。
- 触控目标原则上不小于 44×44 CSS px；紧凑数据表操作不得小于可可靠点击的范围。
- 正文、控件和状态文字满足 WCAG AA 对比度目标。
- 全流程支持键盘导航、可见焦点和语义化标签。
- 遵守 `prefers-reduced-motion`，禁用非必要变换动画。

## 9. 视觉验收

UI 变更提交前必须提供或记录：

- 桌面亮色、桌面暗色、移动亮色、移动暗色。
- default、hover/focus、展开、空态和错误态中适用的状态。
- 无横向溢出、无遮挡、无布局跳动。
- 新组件与相邻页面使用相同 token 和组件语义。

“看起来更现代”不是验收标准；必须指出层级、可读性、任务效率或一致性改善。
