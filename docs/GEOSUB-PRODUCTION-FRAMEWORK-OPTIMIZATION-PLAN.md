# GeoSub 生产框架渐进优化计划

状态：本地规划，未部署生产

## 1. 决策

当前整站 UI 重构暂停，不删除，也不继续向生产扩散。后续前台改进以当前
`origin/main` 的生产框架为基线，采用小批次、可回退、可度量的方式推进。

这条优化线不改变：

- 已上线 URL、canonical、hreflang 和 sitemap 策略；
- 产品、套餐、价格与审核数据模型；
- 首页、产品页、套餐页和指南页的现有信息架构；
- 已经工作的币种切换、地图、价格表、搜索和事件埋点；
- 生产数据库与定时任务。

## 2. Gemini 建议的处理结论

### 直接采纳

1. 价格数字统一使用等宽数字，减少币种和数值切换时的视觉跳动。
2. 在价格表中继续强化本地原价、显示币种折算价、相对基准、税费和核验日期。
3. 桌面端提供紧凑、可吸顶的查价工具栏，但不遮挡正文和表头。
4. 手机端使用纵向信息卡和渐进展开，不使用未优化的横向宽表。
5. 搜索继续支持产品名、套餐名、别名和地区关键词。
6. 价格页与指南页建立有数据依据的双向内链。
7. 数据来源、价格采集日期、汇率基准日期和可信状态继续分开说明。

### 有条件采纳

1. 基准地区切换：先验证现有数据与文案能否正确表达非美国基准，再开放交互。
2. 快速过滤：只提供当前数据能够可靠判断的条件，例如最低价和资料完整度。
3. 教程入口：只有存在对应已发布指南时才显示，不生成空入口。
4. 历史走势：只有连续历史样本足够时才开放，不用稀疏数据画误导性曲线。

### 暂不采纳

1. 主观的“易 / 中 / 难”支付门槛。前台只展示可验证事实及证据完整度。
2. 左右滑动切换排序。它可发现性差，也容易与页面横向手势冲突。
3. 为视觉完整而混入 Web、Google Play 等非正式榜单来源。
4. 无法证明可直接购买时使用 `Product`、`Offer` 或 `AggregateOffer` 富结果。
5. 尚无内容或数据支撑的按钮、筛选器和分类入口。

## 3. 实施批次

### P0：现有价格页可读性

- 核对价格表桌面与手机端的信息顺序；
- 统一数字对齐、日期标签和数据来源说明；
- 收敛状态颜色，只让绿色表达低价或正向结论；
- 保留现有交互，不重写页面骨架。

验收：用户在 10 秒内找到最低价、基准价、数据日期和税费状态；手机端无横向溢出。

### P1：查价效率

- 增加紧凑的吸顶工具栏；
- 增加有证据支持的快速筛选；
- 保持币种、筛选和展开操作客户端即时反馈。

验收：用户两步内完成币种切换、筛选并进入目标地区详情。

### P2：地区决策证据

- 支持最多三个地区的本地价格、折算价和基准差异对比；
- 按需展开价格采集、汇率基准、税务可信度和来源证据；
- 只展示系统已经掌握的订阅条件，不推断未知付款或账号要求；
- AI 与流媒体产品共用同一套判断和展示逻辑。

验收：用户不离开价格表即可比较三个地区并核对关键证据；桌面与手机端均不产生页面级横向溢出。

## 4. 发布规则

每个批次独立提交、独立截图和独立回归。必须通过类型检查、Lint、测试、生产构建，
并在桌面与 390px 手机视口完成浏览器验证。没有观察数据前，不同时上线多个结构性变化。

当前 UI 重构工作区继续保留，仅作为未来备选方案，不作为本优化线的代码来源。
